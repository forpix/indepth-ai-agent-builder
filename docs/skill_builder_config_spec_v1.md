# Skill Builder 配置项精修表 v1.0

> 用途：作为 Claude Code 实现 Skill Builder 一屏的精确输入。每个配置项明确 UI 形态、默认值、取值范围、依赖关系。
>
> 范围：制造业采购协同 Agent Builder 的 Skill Builder Tab——这是 demo 的 C 位，配置项的设计深度决定评审者第一眼的印象。

---

## 0. 全局设计原则

在动手前先约束三件事：

1. **配置项不超过两屏**——Skill Builder 左侧配置区滚动总长控制在 PC 端两屏内，超过两屏的内容用折叠区
2. **默认值要"开箱即用"**——新建一个 Skill，所有配置项都有合理默认值，用户可以不改任何东西直接保存
3. **依赖关系要"可见"**——一个配置项被另一个覆盖或禁用时，UI 上必须有提示，不允许"静默生效"

整体布局（用于 Claude Code 参考）：

```
┌─────────────────────────────────────────────────────────────────┐
│ Skill Builder                          [Low Code | Code] 切换 ▼│
├─────────────────────────────────────────────────────────────────┤
│ ┌─────────────────────────────┐ ┌─────────────────────────────┐│
│ │ 左侧：配置区（可滚动）         │ │ 右侧：实时预览 + 配置说明     ││
│ │                              │ │                              ││
│ │ ▶ Skill 元信息                │ │ ┌──────────────────────┐    ││
│ │ ▶ 触发方式                    │ │ │ Skill 预览卡片        │    ││
│ │ ▶ 筛选规则                    │ │ │（名称、版本、复用数）  │    ││
│ │ ▶ 动作配置                    │ │ └──────────────────────┘    ││
│ │ ▶ 自动化边界与规则优先级       │ │                              ││
│ │ ▶ 通知渠道                    │ │ 当前选中配置项说明：          ││
│ │ ▶ 模型路由策略                │ │ [hover 在某项时显示业务意义]  ││
│ │ ▶ 知识检索（RAG）             │ │                              ││
│ │                              │ │ [底部] 冲突预警面板：         ││
│ │ [保存为模板] [测试运行]        │ │ ⚠️ 检测到 N 处规则冲突       ││
│ └─────────────────────────────┘ └─────────────────────────────┘│
└─────────────────────────────────────────────────────────────────┘
```

## 1. Skill 元信息区

| 配置项 | UI 形态 | 默认值 | 取值范围 | 依赖 | 备注 |
|---|---|---|---|---|---|
| Skill 名称 | 单行文本输入 | "制造业采购交期跟催 Skill" | 1-50 字符 | 无 | 必填；保存时校验重名 |
| 适用行业 | 多选 Tag | ["装备制造", "汽车零部件"] | 装备制造/汽车零部件/电子/半导体/通用 | 无 | 影响下方默认值（比如选"半导体"时关键件阈值更严） |
| 版本 | 只读显示 | "v1.0.0" | 自动递增 | 无 | 保存时自动 +0.0.1，发布到模板市场时手动选大版本号 |
| 描述 | 多行文本 | （空） | 0-200 字符 | 无 | 模板市场展示用，可选 |

**Claude Code 实现备注**：用 shadcn/ui 的 `Input` + `MultiSelect`（可以基于 `Command` 组件搭）+ `Textarea`。

## 2. 触发方式区

四种触发并存，每种独立配置开关。

| 配置项 | UI 形态 | 默认值 | 取值范围 | 依赖 | 备注 |
|---|---|---|---|---|---|
| **定时触发** | Toggle + Cron 输入 | 开启，"0 8 * * *"（每天 8 点） | 任意有效 Cron | 无 | Toggle 关闭时整个 Cron 输入禁用 |
| **手动触发** | Toggle | 开启 | - | 无 | 表示采购员可以从工作台主动调用此 Skill |
| **自然语言触发** | Toggle + 关键词列表 | 开启，["跟催", "未回复", "供应商"] | 1-10 个关键词 | 无 | 表示 Agent Console 里采购员说类似话术时可路由到此 Skill |
| **事件触发** | Toggle + 事件下拉 | 关闭 | "MRP计划变动"/"工单插单"/"采购订单状态变化"/"自定义" | 选"自定义"时显示 webhook URL 输入框 | 至少要开启 1 种触发，否则保存时报错 |

**横向约束**：四种触发至少开启 1 种，UI 上方红色提示"至少开启一种触发方式"。

**Claude Code 实现备注**：每个触发用 `Card` 包裹，顶部 `Switch` 控制启用，启用后展开下方详细配置。

## 3. 筛选规则区

这是配置项最多的一块。设计原则：**每条筛选规则可以独立开关，规则之间是 AND 关系**。

| 配置项 | UI 形态 | 默认值 | 取值范围 | 依赖 | 备注 |
|---|---|---|---|---|---|
| **到货前 N 天** | Toggle + Slider | 开启，7 天 | 1-30 天 | 无 | Toggle 关闭时不参与筛选 |
| **供应商回复状态** | Toggle + Checkbox 组 | 开启，勾选"未回复" | 未回复/已回复延期/已回复确认 | 无 | 至少勾一个，否则报错 |
| **物料属性** | Toggle + Checkbox 组 | 关闭 | 关键件/单一来源/无替代料 | 无 | 三选项可任意组合，至少勾一个 |
| **影响工单状态** | Toggle + 单选 | 关闭 | 影响在制/影响计划/不影响 | 无 | 三选一 |
| **供应商等级** | Toggle + 多选 | 关闭，全选 | A/B/C | 无 | 用 Tag 显示选中等级 |
| **指定采购员** | Toggle + 角色或人员选择 | 关闭 | 全部采购员/按角色/按人 | 无 | "按人"时弹出人员选择器 |

**横向约束**：

- 至少启用 1 条筛选规则，否则全表都会被命中
- 启用 0 条时 UI 上方提示"建议至少启用 1 条筛选规则，否则会命中所有采购订单"

**Claude Code 实现备注**：每条规则用 `Card` + 顶部 `Switch`，启用后才显示下方配置。Slider 用 shadcn 的 `Slider`，Checkbox 用 `Checkbox`。

## 4. 动作配置区

六种动作并存，每种独立开关。配置好筛选规则后，对命中的订单批量执行启用的动作。

| 配置项 | UI 形态 | 默认值 | 取值范围 | 依赖 | 备注 |
|---|---|---|---|---|---|
| **发送跟催通知** | Toggle + 模板下拉 | 开启，"标准跟催模板 v1" | 系统预设 4 个 + 自定义 | 模板下拉可点击"编辑" | 模板内容支持变量 `{供应商名}` `{物料名}` `{到货日}` 等 |
| **标记加急** | Toggle | 关闭 | - | 无 | 启用后命中的订单会在采购单列表显示"加急"标签 |
| **发起二次跟催** | Toggle + 时间间隔 Slider | 关闭，3 天 | 1-7 天 | 仅当"发送跟催通知"开启时可用，否则灰显 | 表示一次跟催后 N 天供应商仍未回复，自动发二次跟催 |
| **派发任务卡给采购员** | Toggle | 开启 | - | 无 | 在采购员工作台显示任务卡（B 端 SaaS 主流形态） |
| **创建异常任务** | Toggle + 升级条件 | 关闭 | 立即创建/二次跟催后创建/N天未回复创建 | 选"N天未回复"时显示天数 Slider | 异常任务会升级到采购主管 |
| **调用其他 Skill** | Toggle + Skill 下拉 | 关闭 | 平台内其他 Skill 列表 | 防止循环调用（同 Skill 不允许） | **多智能体协同的钩子**，比如调用"齐套预警 Skill" |

**横向约束**：

- 至少启用 1 个动作
- "发起二次跟催"依赖"发送跟催通知"——前者关闭时后者灰显且 hover 显示"需先启用'发送跟催通知'"

**Claude Code 实现备注**：模板下拉可以放一个"预览"按钮，弹窗显示模板内容（mock 文本即可）。

## 5. 自动化边界与规则优先级 ⭐ 重点

这是 Skill Builder 里**最能体现平台 PM 产品深度的一节**，必须做扎实。

### 5.1 自动化边界配置

| 配置项 | UI 形态 | 默认值 | 取值范围 | 依赖 | 备注 |
|---|---|---|---|---|---|
| **延期自动同意上限** | Slider | 2 天 | 0-7 天 | 无 | 供应商回复延期且 ≤ 此天数时自动同意，> 此天数进入人工 |
| **关键件人工复核** | Toggle | 开启 | - | 无 | 启用时关键件订单的所有动作都需人工确认 |
| **影响在制工单人工复核** | Toggle | 开启 | - | 无 | 启用时影响在制工单的订单所有动作需人工确认 |
| **跟催次数上限** | Slider | 3 次 | 1-10 次 | 仅当"发起二次跟催"开启时显示 | 达到上限后自动升级异常 |
| **单一来源自动升级异常** | Toggle | 开启 | - | 无 | 单一来源供应商未回复时自动创建异常任务 |

### 5.2 规则优先级（固定，不可配置）⭐

这是 demo 里**评审者最容易问产品深度的地方**。要在 UI 上明确展示三层优先级是**固定的**，让评审者一眼看到"这是平台 PM 设计的产品约束，不是开发者随便堆砌的配置项"。

UI 形态：用一张图（不是配置项），固定显示在"自动化边界"上方：

```
┌─────────────────────────────────────────────────┐
│ 规则优先级（不可配置，系统约束）                  │
├─────────────────────────────────────────────────┤
│ 🛡 安全层    >  📋 业务层  >  ⚡ 效率层          │
│                                                  │
│ 安全层：关键件 / 单一来源 / 影响在制工单         │
│        → 必须人工确认（不可被业务层覆盖）         │
│                                                  │
│ 业务层：延期天数 / 供应商等级 / 客户重要性        │
│        → 默认人工，可配置为自动                   │
│                                                  │
│ 效率层：跟催次数 / 自动同意范围                   │
│        → 默认自动执行                            │
└─────────────────────────────────────────────────┘
```

### 5.3 冲突预警面板（底部固定区）

实时检测配置之间的隐式冲突，在 Skill Builder 右下角固定显示：

| 冲突类型 | 触发条件 | 提示文案 | 严重等级 |
|---|---|---|---|
| 安全层覆盖业务层 | "延期自动同意上限 > 0" 且 "关键件人工复核 = 开启" | "⚠️ 关键件订单即使延期 ≤ N 天也会进入人工确认（被安全层覆盖）" | 黄色 |
| 二次跟催与跟催次数冲突 | "发起二次跟催 = 关闭" 且 "跟催次数上限 > 1" | "ℹ️ 已关闭二次跟催，跟催次数上限实际无效" | 灰色 |
| 筛选规则全空 | 所有筛选规则 Toggle = 关闭 | "🔴 未启用任何筛选规则，此 Skill 会命中所有采购订单" | 红色 |
| 动作全空 | 所有动作 Toggle = 关闭 | "🔴 未启用任何动作，此 Skill 不会执行任何业务操作" | 红色 |
| 自调用循环 | "调用其他 Skill = 当前 Skill 自己" | "🔴 不允许调用自身 Skill（会导致循环）" | 红色 |

**Claude Code 实现备注**：冲突面板用 `Alert` 组件实现，颜色根据严重等级。所有冲突实时计算，不需要点"检测"按钮。

## 7. 模型路由策略 ⭐ v1.1 新增

这一节是 v0.1（GPT 整理版）完全没有的，**强烈建议做扎实**——这是呼应平台级"多模型集成"工程现状的关键。

| 配置项 | UI 形态 | 默认值 | 取值范围 | 依赖 | 备注 |
|---|---|---|---|---|---|
| **意图识别 / 槽位提取** | 模型下拉 | DeepSeek-V3 | DeepSeek-V3 / GPT-4o-mini / 通义千问-Turbo / 文心一言-Lite | 无 | 走低成本模型 |
| **风险判断 / 异常诊断** | 模型下拉 | GPT-4 | GPT-4 / DeepSeek-R1 / 通义千问-Max / 自定义 | 无 | 走推理模型 |
| **话术生成** | 模型下拉 | 通义千问-Plus | GPT-4 / DeepSeek-V3 / 通义千问-Plus / 文心一言-4 | 无 | 中文话术质量优先 |
| **敏感数据场景** | Toggle + 私有模型选择 | 关闭 | 私有 Qwen / 私有 Llama / 自定义 | 无 | 启用后所有敏感数据走私有模型 |
| **默认路由策略** | 单选 | 成本优先 | 成本优先 / 质量优先 / 平衡 | 无 | 决定上述模型选择的偏好 |

**Claude Code 实现备注**：用 shadcn 的 `Select` 组件。每个模型旁边显示一个 hover tooltip：单 token 成本 + 推理速度 + 中文质量评分（mock 数据即可）。

**附加加分项**：可以在这一节底部加一个简短的"路由策略演进路线"提示框：

```
ℹ️ 路由策略演进：
   v1（当前）：静态配置（按场景固定模型）
   v2（规划中）：动态触发（按 token 数 / 置信度切换）
   v3（远期）：自适应路由（基于历史调用 ROI）
```

这个提示框是"我想过这件事的演进"的视觉证据，评审者如果问"你的路由策略会不会太静态"，你能直接指着这个框讲。

## 11. UI 视觉风格约束

- **整体色调**：参考工业软件 ERP官网——蓝灰为主，强调工业级质感
- **不要做的事**：不要做花哨的渐变色、不要做 C 端互联网风格、不要做 dark mode
- **信息密度**：偏高，B 端工具风
- **字体**：中文用思源黑体或苹方，英文用 Inter
- **组件库**：shadcn/ui，颜色用 zinc 系列做主色
